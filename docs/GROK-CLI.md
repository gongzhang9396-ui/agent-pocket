# Grok CLI 接入

当前开发版已接入电脑上的 Grok Build CLI。手机可以打开电脑已有会话继续聊天，也可以新建文本任务、查看流式回复和工具进度、处理单次审批及中断。此功能尚未发布到正式版本；需要配套更新 Host 和 Android。

## 使用

1. 在运行 Host 的同一个 Windows 用户下安装 Grok Build，并执行 `grok login`。已有登录可以复用，不向手机传递模型凭据。
2. 更新 Host 和 Android 后，点击首页顶部的 **Grok**，查看按电脑和项目整理的 Grok 对话。顶部可切换全部、Codex 和 Grok；每项显示当前电脑范围内的任务数量。Grok 入口始终显示，即使还没有任务。
3. 点击 **新建 Grok 任务**，选择电脑、项目和模型并发送文本。Agent 会沿用首页的选择；模型及推理档位来自该电脑的 CLI。安装或登录有问题时，界面显示该 Agent 的错误，其他 Agent 仍可使用。
4. 电脑已有会话自动出现在对应项目中，空闲会话标记为 **跨端续聊**。打开后可阅读历史、加载更早消息并发送下一轮，沿用原会话 ID 和上下文。只有位于该 Host 允许项目范围内的会话会同步。
5. 手机经 Host 创建的 Grok 对话可以查看进度、处理权限请求或中断；完成后可以发送下一轮。返回首页仍停在 Grok 列表，新建时切换 Agent 则返回实际创建的 Agent 列表。Grok 暂不支持运行中追加指令，输入框可以先保留草稿。

默认查找当前用户的 `~/.grok/bin/grok.exe`（非 Windows 为 `grok`），随后使用 PATH。非标准路径可设置 `AGENT_POCKET_GROK`；Windows 安装版也可在本机 `host-config.json` 设置 `grokCommand`。此字段只接受程序路径，不接受命令行拼接。Host 不修改 Grok 的全局配置、模型账号或登录方式。未安装 Codex CLI 不再阻止 Host 启动。

无需手动打开 Grok 终端：手机发送时，Host 会自动启动或连接 Grok 后台并加载会话。电脑需要开机且未休眠、Host 在线、CLI 已安装并且凭据可用。电脑关机、休眠或 Host 离线时不能执行新的消息。

## 在电脑继续同一会话

手机使用 Grok 的本地共享执行器。电脑也要连接同一个执行器才能在两端交替发送，推荐在原项目目录执行：

```sh
grok --leader --resume <原生会话ID>
```

原生 ID 是手机任务 ID 去掉 `grok:` 前缀后的部分。`--leader` 是本机 1.0.13 接受但普通帮助未展示的交互参数，默认 socket 为 `~/.grok/leader.sock`。本命令无需修改全局配置。普通 `grok` 是否使用共享模式还受本机配置和远端开关影响，不能一概视为共享客户端。

已打开的独立终端（例如显式 `--no-leader`）需要等当前执行结束并退出，再用上述命令恢复；不能一边保留独立执行器写入、一边让手机续写同一会话。自定义 socket、sandbox 导致的独立执行模式，以及终端连接失败后回退到内置执行器，也不在共享保证内。Host 不会删除锁或强制结束这些终端。

## 会话与恢复

- Grok 任务使用 `grok:<nativeSessionId>`，不会交给 Codex app-server 或 Desktop Attach。列表合并 Host 管理的任务与原生目录会话；同一个 ID 只显示一次。
- 查看电脑会话只读取当前用户的 `~/.grok/sessions`，不启动 Grok、不加载会话或修改原生锁。只有发送时才建立 Host 侧的续聊记录。首次访问目录后，Host 每 5 秒检查文件变化并通知手机刷新；电脑侧更新以 CLI 已保存的历史为准，不保证终端未落盘内容的逐字同步。
- 原生目录扫描核对实际路径、项目白名单和会话 ID，排除链接逃逸、重复 ID 与尚未写完整的元数据。目录按 Agent 独立分页，翻页使用短期稳定快照，避免 Codex 首屏占满后遮住 Grok 会话。
- 原生历史按约 512 KiB 和最多 100 项分页，长文本按 Unicode 字符边界分块。游标绑定记录位置和历史版本；追加保留翻页连续性，改写或截短触发重新加载。文件发生变化时，最多对 128 MiB 内容验证追加关系，更大文件不沿用未经验证的旧版本。单次倒读最多 64 MiB，单行解析最多 16 MiB，超限会明确提示。
- 原生用户消息、助手回复和工具记录可以显示；不投影系统提示、合成提醒、推理或加密字段，图片以占位文字表示。未写完的尾行等待下一次刷新，损坏记录显示占位提示。元数据已存在但历史暂未就绪的会话仍保留在目录，发送会明确报错且不启动模型。
- 每轮使用 `grok agent --leader stdio` 连接同一个本地执行器。新建调用 ACP `session/new`；续聊调用 `session/load`，再发送 `session/prompt`。同一会话由 Grok 的共享队列执行，手机显示连接中、排队和执行状态；结束时只断开本次连接。连接失败或旧版本不会静默改用独立 writer。
- CLI 原生历史是续聊后的统一记录。执行时叠加 SQLite 中本轮的流式内容，完成后切回原生历史；版本标记使手机清理临时消息 ID，避免重复。分页可从本轮输出一直回到电脑旧历史。历史来源标记使用独立附表，保留旧 Host 的任务表结构和回滚兼容性。
- 手机掉线不会中断执行；恢复连接后从持久事件与历史补齐。Host 重启时会将未完成的连接标记中断，失效审批标记取消，明确提示电脑执行可能仍在继续，不自动重发模型提示词或工具操作。之后能读取 CLI 已保存的输出；未落盘内容不保证恢复。
- 文本分块持久化，历史按约 512 KiB 页预算读取，游标绑定任务和稳定记录位置。工具输出有 32 KiB 的显示上限；超过时明确标记截断。
- 同时最多 4 个 Grok 任务，包含启动中的预留名额。创建和发送使用客户端消息 ID 去重；运行状态、审批与中断均绑定准确的会话和 prompt ID。排队取消还匹配 owner 与队列版本；不会通过通用取消操作停止电脑上的其他轮次。共享广播中的其他轮次输出和权限请求不混入当前手机轮次。

## 能力边界

跨端续聊要求 Grok Build **1.0.13 或更新版本**；当前真实验证版本为 1.0.13。此版本未实现文档中的 `session/set_config_option`；新任务的模型和推理档位通过启动参数及 `session/new` 元数据指定，续聊沿用原会话设置。API 用户复用电脑已有 CLI 凭据，不要求手机额外登录 Grok。

当前不提供图片/附件、Codex Plan/Goal、Grok 与 Codex Desktop 交接，或独立终端执行器的强制接管。Grok 自身的工具和计划进度可以显示，但这不等同于支持 Codex 的 Plan 模式。权限界面只提供单次允许、拒绝和取消；当 CLI 仅提供永久允许选项时，Host 拒绝将“单次允许”扩大为永久授权。新建和恢复都关闭自动审批；未声明文件系统或终端代理能力，工具仍由 Grok CLI 自己执行。

共享保证来自连接同一个 Grok leader，不能只用 `session/load` 成功或 JSONL 文件锁存在来推断。版本升级之后仍需保留队列、取消与权限合约测试，不能仅根据版本号认定新的私有扩展完全兼容。

协议依据：[Grok 官方 ACP 文档](https://docs.x.ai/build/cli/headless-scripting)、[ACP 会话协议](https://agentclientprotocol.com/protocol/v1/session-setup)、[ACP 工具和权限协议](https://agentclientprotocol.com/protocol/v1/tool-calls)，并以本机握手和隔离测试核验实际支持范围。

## 验证

Bridge 全套 130 项测试通过，覆盖真实子进程 NDJSON、跨重启去重、原生续聊、流式与旧历史分页、审批归属、精确取消、容量、失败提示和旧数据库兼容。目录回归覆盖白名单、链接隔离、不写原文件或锁、隐私字段过滤、追加/改写/截短、未完成尾行和变更事件。Android 42 项测试通过，包含共享会话发送能力及队列提示；缺失能力声明仍按禁用处理。

真实 Grok 隔离测试通过：两个 ACP 客户端经同一 leader 排队续聊；取消手机排队项不影响电脑当前轮次；生产 GrokAgent 完成“电脑 ACP → 手机适配器 → 电脑 ACP”三轮同 ID 上下文验证。该次手机适配器首段输出约 2.4 秒，这不是手机网络的端到端延迟，也不能代替交互 TUI 验收。真机已验证电脑会话历史可见、输入和发送可用，并确认手机发送的一轮完成且保存回同一原生会话。先前工具测试收到真实审批并拒绝，目标文件未创建。测试记录位于忽略的 `output/grok/`，不包含在发布包中。
