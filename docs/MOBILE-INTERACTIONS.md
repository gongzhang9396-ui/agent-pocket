# 手机上的问题与审批

手机对话支持选项回答和自由输入。选项不会自动提交；提交中显示进度，只有 Host 确认收到后才显示“已回答”或审批结果。提交失败会显示错误，保留输入供重试。

| 执行方式 | 手机能力 |
| --- | --- |
| Codex Host | 回答原生多题请求，允许一次、拒绝或取消执行审批。刷新后恢复请求和已提交结果。 |
| Codex Desktop | 回答 `request_user_input_async` 异步提问，包括多组选项和自由文本。命令、文件、权限等阻塞审批仍需在 Desktop 处理。 |
| Grok CLI | 单次权限卡片和回应通道；审批独立于历史分页恢复，历史暂不可读时也能处理。 |

Desktop 的异步问题可以由 `agentMessage` 的 `delivery: "async"`、`questions` 字段提供。新版历史缺少这些字段时，桥接器会有界读取本地 rollout，验证会话身份，并且仅在线程中的轮次、消息 ID 与 `request_user_input_async` 调用及其 `accepted: true` 结果匹配时恢复结构化问题。无法核实时不从普通消息猜测问题或选项。桥接器使用原始消息 ID 和问题序号生成稳定的请求标识，回复采用 Desktop 自身使用的 `send_user_message_question_reply` 结构。普通聊天内容不会被当作审批结果，也不会用异步回答绕过执行审批。

读取历史时先索引问题，再按字节切页，因此长任务前面的待回答问题不会被末尾的大段工具输出遮掉。桥接器从原生用户回复恢复回答状态，返回 `pocketQuestion` / `pocketApproval` 卡片及 `interactionItems`。现有请求表提供有界缓存，读取不认领 writer、不恢复执行会话。

新版 Host 声明 `interaction-snapshot-v1`。手机对话在前台时每四秒读取 `thread/interactions`，只更新交互卡片，不替换整段历史；离开页面或进入后台即停止。`thread/interactions` 返回 `items` 和 `execution`，不携带工具日志。旧 Host 不启用此接口。

Grok 的快照直接读取本轮权限状态，不依赖 CLI 历史文件。对于仍在运行的旧 Host，手机在遇到历史版本错误时，可以从 Relay 保留的加密事件中恢复该任务的审批。恢复不回退全局事件游标、不重放文本；校验账号、Host 和事件完整性，按顺序排除已处理或已结束的请求。旧事件没有具体审批结果时，只标记不可操作，不猜测用户选择。此兼容恢复受事件保留期限限制，仍应更新 Host 修复历史读取。

`question/respond` 的 Desktop 异步回答必须同时提供原任务的 `threadId`、稳定 `requestId` 和一项答案。Host 校验请求归属、读取已存在的 Desktop 回答、等待队列提交成功后记录结果；已确认的请求重复提交会返回原结果。Host 原生多题请求必须完成全部问题才会提交。执行连接已经结束的旧审批保留说明，但禁止再次操作。

当前 Desktop 的对外工具管道没有提供阻塞审批列表与响应接口。应用内的 follower 审批方法属于内部窗口通信，尚不能作为外部 Host 通道使用；本版本没有宣称支持这部分远程审批。

验证覆盖：真实 Desktop 任务的问题与已回答状态只读投影、长任务分页、失败后重试、跨任务拒绝、重复提交、原生多题完整性、执行连接退出以及手机事件重放保护。测试使用临时数据库和合成请求，不代替用户回答真实审批。
