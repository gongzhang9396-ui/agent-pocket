## 实际功能

DSH 是 Codex、Grok 之外的独立 Agent，任务 ID 为 `dsh:<nativeSessionId>`。Flutter 和网页按电脑的 `agent/list` 抓取、分页和校验任务目录；提供 DeepSeek 筛选、新建、旧会话历史、实时文字、续聊、模型／推理档位、运行中追加、中断、单次审批，以及多选／自定义问题回答。网页更新后现有 iOS 网页容器可获得同一入口；iPhone 尚未实测。

当前 DSH 不开放 Pocket 附件、Plan／Goal 或任务交接；Codex 原有功能保留。仍走现有端到端加密 Relay，手机不填写另一套 DSH 地址，不接收电脑的模型凭据。

## 运行与安全边界

- 原全局 DSH 的审批实现被 `dsh-purge` 改为自动放行，不能用于 Pocket 审批。使用单独固定的官方 `@deepseek-ai/dsh@0.2.1-rc.2`、npm 锁文件、私有目录权限和文件摘要。原安装、Web profile、凭据和会话保留。
- `dsh-bridge-plugin/prepare-runtime.mjs` 安装并封存独立运行时，记录本机路径及 `DSH_HOME`。不覆盖或封存已有未验证目录。外部 `node_modules` 不进入源码包或 APK。
- 专用 `agent-pocket` profile 只含官方 base/web 和本地插件。全局 `cordis.patch.yml` 存在或专用 profile 被更改时拒绝自动启动，不删除用户配置。
- 父进程继承的 Node IPC 是唯一控制连接；没有公开控制端口或手机侧 DSH token。官方 Web 只监听 loopback 随机端口，不自动打开。协议、固定版本、审批和提问能力全部验证后才开放写操作；失败关闭本次启动的子进程。
- 审批优先权来自实际可见聊天页的短期租约。退出、切任务、断连或超时后，已领取的交互拒绝／取消，不再交由其他回答方执行；未领取才走官方回答链。校验准确的 Agent／session、规范项目路径、交互指纹和一次性答复，不提供永久放行。
- 消息先进入现有 operation ledger，原生 `requestId` 等于 `operationId`。创建前保存确定的 sessionId，再分创建／发送两阶段。丢回执只读查询持久 `user/message.source.rpcId`，不重发或另建会话。部分创建保留空会话和原消息。网页和 Flutter 拒绝错配回执。
- 模型来自实际目录；不调用会改全局默认值的公共 `selectModel()`。固定版本和结构检查后使用会话内下一请求选择。它与电脑共享会话，界面提示交替发送，不保证并发请求间模型选择的原子隔离。
- 独立 DSH 桌面／Web 进程不是同一个执行器。本版不会接管其持有写锁的会话，不删锁或杀用户进程。“电脑 UI 与手机交替续聊”需要在同一 Pocket 管理执行器上另行验收。
